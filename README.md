# Помощник настройки рабочего места для электронной подписи

WPF (.NET 8, MVVM, DI) — автономное приложение для диагностики и настройки рабочего места для работы с электронной подписью.

## Сборка и запуск

```
dotnet build src/SetupAssistant/SetupAssistant.csproj
dotnet run --project src/SetupAssistant/SetupAssistant.csproj
```

## Публикация (self-contained, win-x64, один exe)

```
dotnet publish src/SetupAssistant/SetupAssistant.csproj -c Release
```

Результат: `src/SetupAssistant/bin/Release/net8.0-windows/win-x64/publish/SetupAssistant.exe`
(запускается с запросом прав администратора — задано в `App_Manifest/app.manifest`).

## Конфигурация

Все пути к установщикам, минимальные/рекомендуемые версии ПО и параметры UI — в
`src/SetupAssistant/Config/Config.json` (поддерживает комментарии).

## Дистрибутивы (папка Appendices)

Реальные дистрибутивы лежат в `src/SetupAssistant/Appendices/` и устанавливаются тихо. Папка исключена из git
(репозиторий публичный: лицензионное ПО и приватные ключи `.pem` расширений не публикуются) — после клонирования
разложите файлы по путям из `Config/Config.json`:

| Компонент | Файл | Способ тихой установки |
|---|---|---|
| КриптоПро CSP 5.0.12000 | `Крипто Про Windows\csp-x64-rus.msi` | `msiexec /qn /norestart` |
| КриптоПро ЭЦП Browser plug-in 2.0.15820 | `КриптоПро ЭЦП Browser plug-in\cadesplugin.exe` | `-silent -noroot -noyandex -norestart` |
| Chromium GOST (запасной файл) | `chromium-gost-<версия>-windows-amd64-installer.exe` | mini_installer: `--system-level --do-not-launch-chrome` |
| Контур.Плагин (запасной файл) | `DiagPlugin_user.<версия>.exe` | NSIS: `/S` |
| Плагин Госуслуг | `Плагин Госуслуг\IFCPlugin-x64.msi` | `msiexec /qn /norestart` |
| Драйверы Рутокен | `Рутокен\rtDrivers.x64.msi` | `msiexec /qn /norestart` |
| Расширения (5 шт.) | `расширения chromium\**\*.crx` | политика ExtensionInstallForcelist + локальный `updates.xml` |

Расширения ставятся офлайн: `.crx` копируются в `%ProgramData%\SetupAssistant\Extensions`,
рядом генерируется `updates.xml`, ID вносятся в форс-лист политик Chrome / Chromium / Chromium GOST.
ID расширения берётся из поля `Id` в Config.json. Приватные `.pem` в собранное приложение не копируются
(остаются только в дереве исходников для перепаковки; без `Id` в сборке ID вычислить не из чего).
У расширений из магазина (подписаны ключом магазина) `Id` равен `StoreId`.

**Требование к компьютеру (проверено на Chromium GOST 152).** Политика принудительной установки расширений
из локальной папки (`ExtensionInstallForcelist` + `file:///…updates.xml`) применяется только на **управляемых**
компьютерах: в домене Active Directory, в Azure AD или с MDM. На остальных Chromium помечает политику как
`[BLOCKED]` («компьютер не является корпоративным») и ставит лишь расширения из Интернет-магазина Chrome. Мастер и
диагностика предупреждают об этом («Управление компьютером»). Chromium GOST читает политики из
`HKLM\SOFTWARE\Policies\Chromium`, native-хосты — из `SOFTWARE\Chromium\NativeMessagingHosts` и
`SOFTWARE\Google\Chrome\NativeMessagingHosts`.

**Контур.Плагин** (`DiagPlugin_user`) ставится для текущего пользователя в `%LOCALAPPDATA%\SkbKontur`, в реестре
называется «Диаг.Плагин» (`HKCU\SOFTWARE\SKBKontur\DiagPlugin`), native-хост — `kd.nc` (HKCU). Запускайте мастер
под той учётной записью, для которой настраивается рабочее место: плагины Контура и Госуслуг пишут данные в
профиль того, кто их устанавливает. Расширению «Госплагин» нужен свой native-хост `gosuslugi.plugin`, которого
не ставит ни один из дистрибутивов проекта.

**Chromium GOST** содержит встроенное расширение КриптоПро (так указано на странице КриптоПро), отдельное
расширение КриптоПро для него не нужно. Native-хост `ru.cryptopro.nmcades` разрешает только расширения с
магазинными ID (`iifchhfn…`, `pfhgbfnn…`) и встроенное `epebfceh…`; расширение с перепакованным ID к нему
подключиться не сможет.

## Удаление компонентов (откат настройки)

Кнопка «Удалить компоненты» на главном экране. Экран сначала показывает, что найдено на компьютере (ничего не
меняя), затем по подтверждению удаляет в обратном порядке: Контур.Плагин, Плагин Госуслуг, плагин
КриптоПро, драйверы Рутокен, КриптоПро CSP. Chromium GOST не удаляется. Компоненты ищутся в «Программах и компонентах» (HKLM и HKCU) по названиям
из раздела `Uninstall` в `Config.json`: MSI удаляется через `msiexec /x` по коду продукта (строка удаления КриптоПро в
реестре содержит `/I` — «изменить», она не используется), EXE — командой из реестра плюс `Args`; перед удалением
закрываются процессы браузера и плагинов. Результат каждого шага определяется по реестру, а не по коду возврата.
MSI запускается с `MSIRESTARTMANAGERCONTROL=Disable`: приложение при старте подгружает DLL КриптоПро
(`Common Files\Crypto Pro\AppCompat\*`, после диагностики — `cpcsp.dll`), и «Диспетчер перезапуска» Windows Installer
иначе закрывает его посреди удаления (событие RestartManager 10002). Занятые файлы удаляются при перезагрузке,
после удаления КриптоПро CSP перезагрузка обычно нужна. Если удаление прервано, его можно запустить снова: план
покажет только то, что осталось.

Затем удаляются политика установки расширений (только записи приложения, указывающие на его `updates.xml`; чужие
записи остаются), репозиторий расширений, временные загрузки, остаточные папки (`LeftoverPaths`) и ветки реестра
(`LeftoverRegistryKeys`), кэш единого exe. Если какой-то компонент не удалился, остаточные данные не трогаются.

**Не удаляются никогда:** ключи, ключевые контейнеры, содержимое токена и ветка реестра `HKCU\SOFTWARE\Crypto Pro`
(в ней хранятся контейнеры) — путь с сегментом «Crypto Pro» отвергается проверкой. Необязательный флажок
дополнительно удаляет из хранилища «Личное» сертификаты, привязанные к провайдеру КриптоПро (вернуть их можно
повторной настройкой с токена). Запускайте под той учётной записью, под которой настраивали: Контур.Плагин и данные
Госуслуг пользовательские.

## Единый exe

`tools\Build-SingleExe.ps1 [-OutputDir ...]` (PowerShell 7; если целевой exe запущен, укажите другую папку) собирает `dist\SetupAssistant-Full.exe`: публикует приложение и
дописывает в конец exe архив с `Config`, `Appendices` и `LatoFont` (подвал `SAPAYLD1` + длина архива).
Приложение читает эти данные само и **распаковывает файл только в момент, когда он нужен** (в
`%ProgramData%\SetupAssistant\Payload\<id сборки>`; кэш предыдущих сборок удаляется при запуске), поэтому
запуск быстрый, а Chromium (120 МБ) не распаковывается, если скачался свежий. Файл `Config\Config.json` или
дистрибутив рядом с exe имеют приоритет над встроенными: так можно подменить конфиг без пересборки. Журнал
пишется в `Logs` рядом с exe. Подписывать нужно готовый `SetupAssistant-Full.exe` (данные находятся и в
подписанном файле).

Обновить единый exe: на компьютере с интернетом запустить `ExtensionUpdater.exe src\SetupAssistant`
(обновит `Config.json` и файлы в `Appendices`), затем `tools\Build-SingleExe.ps1`.

## Обновление расширений и дистрибутивов

`ExtensionUpdater.exe` запускается на компьютере с интернетом (во внутренней сети магазин Chrome недоступен):
положите его рядом с `SetupAssistant.exe` и запустите двойным щелчком либо укажите папку приложения аргументом.

- **Расширения:** версии сверяются с сервером обновлений Chrome, новые `.crx` скачиваются с проверкой SHA-256.
- **Дистрибутивы** (раздел `Installers`): по `UpdateUrl` / `DownloadUrl` проверяются КриптоПро Browser plug-in,
  Chromium GOST (GitHub), Контур.Плагин, Плагин Госуслуг, драйвер Рутокен. Новый файл принимается, только если
  у него действительная подпись Authenticode и издатель содержит `ExpectedSigner`. КриптоПро CSP зафиксирован
  и не обновляется. Та же проверка подписи выполняется приложением при скачивании во время установки.
- `--check` — только проверить; `--prune` — удалить старые версии (файл из `Config.json` и `.pem` не
  удаляются; при запуске двойным щелчком утилита спросит подтверждение для `.crx`); `--prune-only` — только
  удалить старые `.crx` без обращения к сети. Перед правкой создаётся
  `Config.json.bak`. Приложение при запуске (если есть интернет) показывает уведомление о новых версиях
  расширений, то же по кнопке в «Настройках».
- Сборка: `dotnet publish src/ExtensionUpdater/ExtensionUpdater.csproj -c Release` (результат —
  `src/ExtensionUpdater/bin/Release/net8.0/win-x64/publish/ExtensionUpdater.exe`, около 34 МБ).

**КриптоПро ЭЦП Browser plug-in** (`Appendices\КриптоПро ЭЦП Browser plug-in\cadesplugin.exe`, 2.0.15820)
скачивается без регистрации: достаточно анонимной сессии (страница плагина → `get_2_0`). Установщик
запускается с `-silent -noroot -noyandex -norestart`: `-root` по умолчанию ставит в систему корневые
сертификаты из архива, а `-yandex` предлагает Яндекс.Браузер.

## Что проверяет и настраивает мастер

Шаги: КриптоПро CSP → Browser Plugin → драйвер Рутокен → Chromium GOST → Контур.Плагин → Плагин Госуслуг →
расширения браузера → сертификаты УЦ → сертификат с токена в хранилище → итоговая диагностика.

- **Драйвер Рутокен**: `Appendices\Рутокен\rtDrivers.x64.msi` (5.3.00.0000, скачан с rutoken.ru).
  **Плагин Госуслуг**: `Appendices\Плагин Госуслуг\IFCPlugin-x64.msi` (нужен расширению «Госуслуги»).
- **Сертификаты УЦ** (`CaCertificates`): по умолчанию список пуст (сертификаты ставятся политиками), шаг и
  проверка скрыты. Если заполнить — импорт только при совпадении отпечатка, действующем сроке и признаке УЦ.
- **Сертификат с токена**: после подключения носителя запускается `csptest -absorb -certs -autoprov`.
- **Диагностика** дополнительно показывает: провайдеры КриптоПро (типы 80/81/75), ключевые контейнеры и
  считыватели (`csptest`), native messaging-хосты расширений (`NativeMessaging`), COM CAdESCOM,
  наличие «Континент-АП» (только определение), цепочку доверия, Key Usage, EKU и политики сертификатов.
- Намеренно не реализовано: подавление лицензионных запросов КриптоПро, исключения CSP, включение старых
  шифров и ручная регистрация OID. «Доверенные узлы» плагина не настраиваются приложением: по ADMX-шаблону
  плагина это политика `HKLM\Software\Policies\Crypto-Pro\CadesPlugin` (`TrustedSites`, `DisableSitesNotInList`).

## Возможности интерфейса

Оформление — [ModernWpf](https://github.com/Kinnara/ModernWpf): боковое меню, светлая/тёмная тема (Настройки → Оформление),
Mica на Windows 11.

- **Главная** сразу собирает сведения о рабочем месте: компьютер в домене или нет, что установлено (с версиями), что не
  установлено и подключён ли носитель. Не на каждом компьютере нужен весь набор, поэтому «не установлено» — это
  информация, а не ошибка (в диагностике — статус «К сведению»). Предупреждением остаётся только установленный компонент
  с версией ниже рекомендуемой. «Выбрать недостающее в мастере» открывает мастер с отмеченными недостающими
  компонентами, ничего не запуская.
- **Мастер**: предварительная проверка (права, место на диске, дистрибутивы, сеть, ожидающая перезагрузка, занятость
  установщика Windows), флажки выбора компонентов, уже установленное пропускается (кнопка «Переустановить установленные»
  отменяет это), «Повторить» у шага и «Повторить неудачные», итоговая сводка с экспортом отчёта.
  Если нужна перезагрузка, «Перезагрузить и продолжить» ставит однократный автозапуск `--resume` (HKCU RunOnce):
  после входа приложение само определит, что осталось исправить, и продолжит.
- Когда нужно действие пользователя (подключить носитель, ввести PIN-код), показывается окно ожидания, значок на панели
  задач мигает и становится жёлтым. Закрытие окна во время установки или удаления требует подтверждения.
- **Диагностика**: группы, фильтр «Только проблемы», счётчики, «Исправить» в строке, копирование.
  **Сертификаты**: срок действия, поиск, панель подробностей, слежение за подключением носителя.
  **PIN-код носителя**: смена PIN-кода пользователя или администратора (пароль электронной подписи) как в «Панели
  управления Рутокен» — через PKCS#11-драйвер `rtPKCS11ECP.dll` (Рутокен) или `jcPKCS11-2.dll` (JaCarta) из System32.
  PIN-коды не сохраняются и не попадают в журнал; для заблокированного PIN предупреждение, разблокировка — в панели Рутокен.
  **Тест подписи**: подписывает тестовые данные выбранным сертификатом через КриптоПро CAdESCOM (так же, как браузерный плагин) и
  проверяет подпись; по этапам видно, где именно сбой. Ничего не сохраняется и не отправляется.
- **Что делать**: у предупреждений диагностики (выберите строку) и у шагов мастера с проблемой есть короткий совет
  (например, почему расширения не применяются вне домена).
- **Пакет для поддержки** (Настройки или Журнал; `--support-bundle файл.zip`): журналы за 7 дней, диагностика, обзор, конфигурация.
  Сертификаты добавляются только по вашему согласию; PIN-кодов, ключей и содержимого токена в пакете нет.
- **Удобство и доступность**: `Ctrl+1…9` — разделы по порядку меню, `F5` — обновить страницу, `Esc` — закрыть окно ожидания;
  значок в области уведомлений и уведомление Windows о завершении, пока окно свёрнуто; размер интерфейса 100–150 %
  (Настройки); при высокой контрастности Windows Mica отключается; у основных элементов заданы имена для экранного диктора.
  При первом запуске показывается приветствие из трёх шагов (вернуть: Настройки → «Показать приветствие снова»).
  **Журнал**: фильтр по уровню, поиск, слежение за новыми записями, копирование.

## Режимы командной строки

Для запуска без окна (GPO, SCCM) нужны права администратора. Вывод печатается в консоль, из которой запущено приложение
(или в файл при перенаправлении); результат также попадает в журнал.

```
SetupAssistant.exe --check  [--report отчёт.pdf]                      проверить рабочее место
SetupAssistant.exe --silent [--reinstall] [--with-token] [--report отчёт.pdf]
                                                                      установить и настроить без вопросов
SetupAssistant.exe --help
```

`--silent` не выполняет шаг «сертификат с носителя» (нужен подключённый токен и ввод PIN-кода), пока не указан `--with-token`.
Коды возврата: `0` — всё в порядке (недостающие компоненты и «не в домене» — к сведению), `1` — предупреждения, `2` — ошибки, `3` — установка невозможна (предварительная
проверка), `4` — неверные аргументы.

## Архитектура

- `Models` — доменные модели (компоненты, сертификаты, конфигурация, журнал, отчёт).
- `Services/Interfaces` + `Services` — по одному сервису на область ответственности
  (реестр, система, установка, КриптоПро, браузеры, расширения, токены, сертификаты,
  диагностика, отчёты, логирование, конфигурация, навигация, диалоги).
- `ViewModels` — MVVM (CommunityToolkit.Mvvm), навигация через `INavigationService`.
- `Views` — экраны: главный, диагностика, мастер настройки, сертификаты, журнал, настройки.
- `App.xaml.cs` — регистрация зависимостей через `Microsoft.Extensions.DependencyInjection`.
